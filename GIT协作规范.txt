二、每次开工的标准流程（拉取 → 干活 → 提交 → 推送）
----------------------------------------------------------------
1. 开工先同步（每天必做、换电脑必做）：
     git pull --ff-only origin main
   本地有未推送提交时改用：
     git pull --rebase origin main
2. 干活：按第一节的目录规则放文件、按 README 的命名规范改名、
   同步更新 00_文档/05_资产状态清单.txt。
3. 提交（一个主题一个提交，例：入库一个道具包=一个提交）：
     git add -A
     git commit -m "入库XX资产：内容简述"
   提交信息格式：动词+对象+范围（入库/修正/更新/归档…）。
4. 推送：
     git push origin main
   被拒绝（远端有新提交）→ 回到第1步同步后再推，不要强推。

----------------------------------------------------------------
三、四条红线（违反会破坏全队工作）
----------------------------------------------------------------
1. 禁止 git push --force 和任何改写历史的操作（rebase 只用于
   同步自己未推送的提交）。
2. 禁止在仓库根目录新建任何文件夹或散文件（唯一结构见第一节）。
3. 单文件不超过 50MB 一律不提交（10秒1080p视频、成片等大文件
   本地留存或走 GitHub Releases；PNG/TXT 放心提交）。
4. 二进制文件（图片/视频/音频）冲突时不做手工合并——以文件名
   版本号更高的一方为准，另一方改名升版重新提交。

----------------------------------------------------------------
四、常见问题
----------------------------------------------------------------
Q: push/pull 连不上 github？
A: 先试走本机代理（2026-10-25实测：直连超时8连败，代理一次成功；
   端口看自己梯子的HTTP代理口，当前机器为12450，查法：
   设置→网络→代理，或注册表 Internet Settings 的 ProxyServer）：
     git -c http.proxy=http://127.0.0.1:12450 push origin main
   代理口失效时改回直连重试；仍不通可先用镜像拉取（只读，仅拉取用）：
     git fetch https://gh-proxy.com/https://github.com/Pyc718672103/Macau-AIGC-competition.git main
     git merge --ff-only FETCH_HEAD
   推送必须直连或代理成功后再做。

Q: 拉下来发现同事的文件放错目录了？
A: 不要原地留着，也不要各自开新目录——按规范移到正确目录并在
   提交信息里写明"归位"。本仓库历史上已归位过：
   蓝的回信_道具资产_v1/ → 03_道具资产/（2026-10-25）
   文化符号的现代演绎/   → 00_文档/14、15（2026-10-25）

Q: 文档怎么编号？
A: 00_文档 从01顺延（当前用至17），资产类文档格式：
   NN_资产类_内容_v版本.txt

Q: AI协作（ZCode/Codex等）怎么接手？
A: 读 AGENTS.md，按其中四档状态口径更新资产状态清单。
